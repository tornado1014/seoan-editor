# 서안 (Seoan)

**특허 전자출원 명세서(`.HLT`)를 맥과 윈도에서 열고, 고치고, 제출파일까지 만드는 편집기**

특허청 전자출원에 쓰는 명세서는 `.HLT` 형식이고, 이 형식을 다루는 공식 도구는 윈도 전용입니다. 그래서 맥을 쓰는 사람은 명세서 하나를 확인하려 해도 윈도 PC를 거쳐야 했습니다. 서안은 그 왕복을 없애려고 `.HLT` 형식을 독자적으로 해석해 만든 데스크톱 편집기입니다.

> 서안은 특허청이나 공식 전자문서 작성 소프트웨어와 **관련이 없는 독립 프로젝트**입니다.
> 실제 출원 전에는 반드시 특허청 공식 소프트웨어로 파일을 열어 확인하세요. 자세한 내용은 아래 [주의](#주의)를 보세요.

---

## 할 수 있는 것

### 열기
| 형식 | 설명 |
|---|---|
| `.HLT` | 명세서 원본 |
| `.hlz` | 제출용 묶음(KIPO XML + 도면) |
| `.fin` | 최종본 제출 세트 |

### 만들기
- **불러와 HLT 만들기**: 워드(`.docx`), KIPO XML(`.xml`), HML(`.hml`)을 새 `.HLT`로 만듭니다. 만들 때 **PCT 국내진입**과 **국내 출원** 중 하나를 고릅니다(둘은 표제와 쪽 나눔 규칙이 다릅니다).
- **제출파일 만들기**: 지금 문서로 `.hlz`와 `.fin`을 만듭니다.
- **보정서 만들기**: 최종본 `.fin`(보정 전)과 지금 문서(보정 후)를 비교해 보정서 `.dta`가 든 새 `.fin`을 만듭니다.
- **인쇄 PDF**: 쪽 배치 그대로 PDF로 냅니다.

### 고치기
쪽 화면에서 바로 고칩니다(WYSIWYG). 쪽 나눔은 공식 소프트웨어의 인쇄 결과와 맞추도록 만들었습니다.

- 글 입력과 수정, 문단 나누기·붙이기, 되돌리기·다시 하기
- 글자모양: 굵게, 기울임, 밑줄, 위첨자, 아래첨자, 글자 크기
- 문단 정렬: 양쪽, 가운데, 왼쪽
- 강제 쪽나눔: `⌘ + Enter`(맥) / `Ctrl + Enter`(윈도)
- Tab 문자 입력
- 찾기·바꾸기(글자모양 조건 포함)
- 표 칸 글 고치기
- 식별항목(【청구항 N】 등) 넣기·지우기, 문단번호 넣기
- 수식 넣기(LaTeX), 화학식 넣기(구조식 그리기)

【청구범위】·【요약서】·【도면】은 항상 새 쪽에서 시작합니다.

## 설치

[Releases](https://github.com/tornado1014/seoan-editor/releases/latest) 에서 운영체제에 맞는 설치 파일을 받으세요.

| 운영체제 | 파일 | 설치 |
|---|---|---|
| macOS 12 이상 (Apple Silicon · Intel) | `seoan_<버전>_….dmg` | 열어서 앱을 「응용 프로그램」으로 끌어 놓습니다 |
| Windows 10/11 (x64) | `seoan_<버전>_…-setup.exe` | 실행하면 사용자 계정에 설치됩니다(관리자 권한 불필요) |

- **macOS:** 애플 공증을 받지 않은 앱이라 처음 열 때 경고가 뜹니다. 앱을 **우클릭 → 열기**로 한 번 열면 그다음부터는 그냥 열립니다.
- **Windows:** SmartScreen 경고가 뜨면 **추가 정보 → 실행**을 누르세요.

설치하면 `.HLT`·`.hlz`·`.fin` 파일을 더블클릭해 서안으로 열 수 있습니다.

**업데이트:** 새 판이 나오면 앱을 켤 때 알려 줍니다(메뉴의 「업데이트 확인…」으로도 확인할 수 있습니다). 설치를 고르면 열린 문서를 저장할지 먼저 묻고, 설치한 뒤 다시 켭니다.

## 쓰는 법 (빠른 시작)

1. **워드 명세서로 시작하기:** 「불러와 HLT 만들기」 → `.docx` 선택 → 출원 종류 선택 → 저장 위치 선택. 만들어진 `.HLT`가 바로 열립니다.
2. **고치기:** 쪽 위를 눌러 커서를 두고 입력합니다. 글자모양은 글을 고른 뒤 툴바 단추나 `⌘/Ctrl + B·I·U`를 누릅니다.
3. **저장:** 「다른 이름으로 저장」. 원본 파일은 덮어쓰지 않습니다.
4. **제출파일:** 「제출파일 만들기」 → `.hlz` 위치 선택. 같은 폴더에 `.fin`도 만들어집니다.
5. **확인:** 만든 파일을 **공식 소프트웨어에서 한 번 열어** 내용을 확인한 뒤 제출하세요.

## 주의

- **독립 구현입니다.** `.HLT` 형식은 공개 사양이 없어, 실제 파일을 분석해 해석했습니다. 대부분의 문서에서 공식 소프트웨어와 같은 결과를 내도록 검증했지만, 모든 경우를 보장하지는 않습니다.
- **제출 전에는 공식 소프트웨어로 확인하세요.** 서안이 만든 `.HLT`·`.fin`은 공식 소프트웨어에서 열어 보고, 화면과 인쇄를 확인한 뒤 제출해야 합니다. 서안으로 만든 파일 때문에 생긴 출원상의 불이익에 대해 개발자는 책임지지 않습니다.
- **지원 범위:** PCT 국내진입 명세서, 국내 출원 명세서, 의견서, 보정서를 대상으로 합니다. 그 밖의 서식은 열리더라도 고치거나 제출파일을 만들 수 없을 수 있습니다.
- **글꼴:** 화면은 바탕체를 씁니다. 바탕체가 없는 맥에서는 비슷한 글꼴로 대신 그리므로, 영문 글자 간격이 인쇄와 조금 다르게 보일 수 있습니다(저장되는 파일에는 영향이 없습니다).
- **아직 안 되는 것:** 오른쪽 정렬, 새 서식으로 빈 문서 만들기 등.

## 개발

| 경로 | 내용 |
|---|---|
| `crates/hlt-core` | `.HLT` 판독 · 생성 · 편집 세션 · KIPO XML/제출파일/보정서 · 쪽 배치 · PDF (Rust) |
| `crates/hlt-cli` | 같은 기능의 명령줄(JSON 계약 `contracts/*.schema.json`) |
| `apps/hlt-desktop` | Tauri 데스크톱 앱(맥 · 윈도) |

```sh
cargo test -p hlt-core -p hlt-cli                 # 합성 자료로 도는 테스트
cd apps/hlt-desktop && npm ci && npx vitest run   # 화면
bash apps/hlt-desktop/scripts/install-mac.sh      # 맥 앱 빌드 · 설치
```

**릴리스:** `tauri.conf.json` 의 `version` 을 올리고 같은 판의 태그(`v0.6.4` 등)를 올리면, GitHub Actions(`.github/workflows/release.yml`)가 맥·윈도 설치 파일과 업데이트 파일(`latest.json` · 서명)을 만들어 Release 에 올립니다. 업데이트 서명 키는 저장소 시크릿에만 있습니다.

실제 출원 문서는 저장소에 넣지 않습니다. 실제 문서로 재는 테스트(`#[ignore]`)는 그 자료가 있는 환경에서만 돕니다.
